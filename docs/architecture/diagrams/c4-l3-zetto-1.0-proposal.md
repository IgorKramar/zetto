# zetto 1.0 — компоненты одного Rust-бинарника

Статус: предложение от 2026-10-29. Детализация L3; блоки внутри бинарника — модули, не отдельные процессы или пакеты. Внешние ресурсы показаны как контекст. [Полный проект](../research/2026-10-29-zetto-1.0-design.md).

```mermaid
flowchart TB
    subgraph binary["zetto — один Rust-бинарник"]
        CLI["CLI · Rust / clap"]
        TUI["TUI · Rust / Ratatui + Crossterm"]
        APP["Операции приложения · Rust"]
        FORMAT["Модель заметки и формат · Rust / pulldown-cmark + YAML"]
        VAULT["Файлы и восстановление · Rust / filesystem"]
        INDEX["Индекс и поиск · Rust / rusqlite"]
        EDITOR["Запуск редактора · Rust / process"]
        CLI -->|"Типизированные операции"| APP
        TUI -->|"Те же операции через фоновые задачи"| APP
        APP -->|"Разбор и проверки"| FORMAT
        APP -->|"Чтение и безопасная запись"| VAULT
        APP -->|"Поиск, граф и сверка"| INDEX
        APP -->|"Редактирование рабочей копии"| EDITOR
        INDEX -->|"Разбор изменившихся файлов"| FORMAT
        INDEX -->|"Чтение состояния файлов"| VAULT
    end
    FILES["Хранилище · Markdown / локальная FS"]
    DB["Производный индекс · локальная SQLite FTS5"]
    EXTERNAL["Редактор пользователя · внешний процесс"]
    VAULT -->|"Файлы, блокировки, recovery"| FILES
    INDEX -->|"SQL / короткие транзакции"| DB
    EDITOR -->|"Запуск с аргументами без shell"| EXTERNAL
    EXTERNAL -->|"Правка рабочей копии"| FILES
```

Стрелки обозначают вызовы/зависимости. Производный индекс можно пересоздать; Markdown, inbox и recovery содержат пользовательские данные. CLI и TUI не зависят друг от друга.
