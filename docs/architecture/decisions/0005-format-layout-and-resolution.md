# ADR-0005: Зафиксировать размещение заметок и однозначное разрешение ссылок

- **Дата**: 2026-10-29
- **Статус**: Accepted — принято Igor Kramar 2026-10-29
- **Автор**: Igor Kramar
- **Уточняет**: ADR-0002 (источник resolve и чтение), ADR-0003 (порядок resolver), ADR-0004 (alias и YAML-writer)

## Контекст

[Предложение 1.0](../research/2026-10-29-zetto-1.0-design.md), §§4–6,
и [контракт этапа 0](../../contracts/stage-0.md) требуют одинакового поведения
CLI, TUI и экспорта. ADR-0002 разрешает переименование при чтении,
ADR-0004 выбирает первый alias по времени и одновременно обещает verbatim
сохранение через сериализатор, который этого не обеспечивает.

## Решение

Опубликованные заметки — `<ULID>-<slug>.md` непосредственно в корне,
черновики — в `inbox/`, вложения — в `assets/`. Идентичность задаёт frontmatter
`id`; имя проверяется как инвариант, а не служит обходом неверного frontmatter.
Один ULID в нескольких файлах всегда неоднозначен. Чтение не меняет байты,
имена или `updated`. Несовпадение slug исправляет только явная операция.

Порядок resolver и YAML-профиль заданы в [format-v1](../../format-v1.md).
После совпадения категории неоднозначность завершает разрешение: fallback
не выбирает другой файл. Alias сравниваются через Unicode lowercase без
locale и без транслитерации; отключения по числу заметок нет. Создаваемые
ссылки содержат полный канонический ULID. Код, embeds, anchors и block refs
не создают графовых рёбер; неподдержанное остаётся буквальным текстом.

Кандидат YAML — `serde-saphyr 2.0.0`, прошедший [корпус](../../../tests/corpus/yaml.json)
в [проверочном стенде](../../../tools/format-probe/src/lib.rs). Разбор в дерево
значений предшествует независимой проверке полей. Writer сохраняет значения
всех неизвестных полей поддерживаемого YAML-профиля, включая вложенные.
Комментарии, порядок ключей, исходные кавычки и anchors не гарантируются;
это семантическое сохранение, а не verbatim. Тело не переформатируется.
Каноническая запись стабильна при повторении, произвольный исходный YAML
не обязан сохраняться побайтно. Неподдержанные конструкции запрещают
управляемую запись, raw-чтение остаётся доступным.

## Последствия

Ошибочная связь не подменяется другой заметкой. Переиндексация не меняет
пользовательские данные. Цена — явные ambiguous-диагностики и необходимость
выбора ULID. Полное сохранение оформления YAML потребовало бы другого writer;
для 1.0 эта гарантия не заявляется. Результат стенда обосновывает выбор
зависимости для проверенного YAML-профиля; применение в приложении предстоит.

## Рассмотренные альтернативы

1. **Сохранить ADR-0002–0004 без уточнений.** Меньше изменений документов,
   но чтение становится записью, а alias может вести к ошибочному знанию.
2. **CST и сохранение YAML побайтно.** Сохраняет комментарии и anchors,
   но добавляет сложную модель редактирования до появления приложения.
3. **Только ULID при чтении.** Самый простой resolver, но теряется уже
   принятая совместимость Markdown и aliases. Генерация остаётся ULID-only.
