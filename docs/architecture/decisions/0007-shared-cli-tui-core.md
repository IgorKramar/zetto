# ADR-0007: Вызывать общее ядро операций из CLI и TUI

- **Дата**: 2026-10-29
- **Статус**: Accepted — принято Igor Kramar 2026-10-29
- **Автор**: Igor Kramar

## Контекст

[Предложение 1.0](../research/2026-10-29-zetto-1.0-design.md), §§3, 8–9,
и [контракт этапа 0](../../contracts/stage-0.md) требуют равноправных CLI/TUI.
В текущем дереве нет приложения; структура старого прототипа не является API.
Разные проверки сохранения в двух интерфейсах сделали бы безопасность
зависимой от способа запуска.

## Решение

Один Cargo package, `lib.rs` и `main.rs`. Модули `note`, `format`, `vault`,
`app`, `cli`, `tui`, `editor`, `config`; `index` появляется при реальной нужде
в v0.2. В v0.1 производный каталог в памяти, полный обход допустим.
`app` принимает типизированные параметры и возвращает результат с данными,
диагностиками, признаком сохранения и recovery; не знает stdout, клавиатуру
и ratatui. Формат не знает filesystem; файловый слой не знает UI.

CLI сериализует результаты по [контракту](../../contracts/cli-v1.md).
TUI преобразует ввод в `Action`, вызывает те же операции и отображает те же
rule IDs и ошибки. Палитра и клавиши ссылаются на один перечень действий.
TUI не запускает CLI-подпроцессы и не пишет файлы напрямую.
Диск/поиск в v0.2 выносятся в std-поток с ограниченными очередями,
request ID и отменой; render не делает I/O. До этого минимальный TUI
может работать синхронно, без обещаний производительности v0.2.

Без TTY интерактивный режим не запускается. При запуске внешнего редактора
и выходе восстанавливается терминал, включая путь ошибки/паники. Проверки
PTY обязательны до beta. Новая зависимость вводится только с потребляющим её
сценарием, lockfile и проверкой MSRV; async-runtime, traits для каждого модуля
и workspace микрокрейтов заранее не создаются.

## Последствия

Один набор операций обеспечивает одинаковую сохранность и диагностики.
Терминальный lifecycle остаётся обязанностью TUI-адаптера и требует реальных
PTY-проверок; unit-тест библиотеки его не доказывает. Конкретные Rust-типы
не являются стабильным SDK 1.0.

## Рассмотренные альтернативы

1. **Логика внутри подкоманд и экранов.** Дешевле первый экран, но проверки
   публикации и конфликтов расходятся.
2. **TUI вызывает CLI и читает JSON.** Повторно использует команды, но каждый
   переход создаёт процесс и усложняет отмену, состояние и диагностики.
3. **Многокрейтовый workspace с портами для всех слоёв.** Формально сильнее
   изоляция, но пока нет нескольких потребителей/реализаций, оправдывающих цену.
