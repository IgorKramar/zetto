# Архитектурное ревью v0.2: поиск, индекс и фоновые операции

Автор: Igor Kramar. Область — изменения `feat/search-index-concurrency`
относительно слитого v0.1, [план v0.2](../../plans/2026-10-30-v0.2-search-index-concurrency.md).

## Status

**Applied 2026-10-30** — written 2026-10-30 by /architect:review.

## Summary

SQLite/FTS5 добавлен как производный слой запросов, общий для CLI и TUI.
Главный риск — рассогласование файлов, графа и поисковой выдачи при нескольких
процессах; generation/revision, транзакционные snapshots и независимая файловая
запись задают явные границы согласованности. Фоновый worker отделяет терминал
от диска и не отменяет уже принятые записи.

## Conformance with ADRs

| ADR | Результат |
|---|---|
| 0001 | Соответствует: один package/binary `zetto`; новая конфигурация бренда не вводится. |
| 0002–0004 с уточнениями 0005–0008 | Соответствует: ULID, slug, YAML/frontmatter и формат ссылок сохранены; исторические разрешения записи при чтении и выбора первого alias не возвращены. |
| 0005 | Соответствует: `Resolver` общий для файлового каталога, индекса и публикации; карты ускоряют те же категории разрешения. Дубликаты представимы отдельными file keys. Inline tags производны, writer их не добавляет в YAML. |
| 0006 | Соответствует: `finish_write` помечает индекс после освобождения vault-lock; отказ сохраняет saved/ID/path/recovery. Файловые операции и doctor не требуют доступной SQLite. Индекс размещён вне vault в приватном XDG cache. |
| 0007 | Соответствует: CLI/TUI вызывают App; render не обращается к БД. Worker использует ограниченные очереди, отмену чтения и IDs, перед редактором терминал восстанавливается. Аварийное сохранение формы выполняется после остановки интерактивного режима. |
| 0008 | Соответствует: capture без связи, условия publish и явный root сохранены. Поисковый индекс не используется как основание для потенциально устаревшей проверки публикации. |
| 0009 | Соответствует: обход вне SQLite write transaction; commit сверяет generation и revision. Files/edges/tags/aliases/diagnostics/FTS обновляются одной транзакцией, cached show/links/search читаются одним snapshot. Rebuild не заменяет файл БД. Watcher — сигнал, full страхует потерю событий. |

Проверенные границы: `src/app.rs` (операции/файловый эталон),
`src/app/query.rs` (запросы), `src/index.rs` (SQLite/сверка),
`src/resolver.rs` (разрешение), `src/tui/worker.rs` (фоновое исполнение),
`src/tui.rs` (состояние/терминал), `src/cli.rs` (машинный адаптер).
SQLite использует общий тип каталога App, но не зависит от UI или stdout;
нового стабильного Rust SDK здесь нет.

## Blocking issues

Архитектурных блокеров не обнаружено. Локальные дефекты корректности вынесены
в отдельное ревью кода и должны быть закрыты до отправки PR.

## Non-blocking suggestions

- **suggestion: S-1.** Сохранить измеренный предел 50k в документации: каталог
  метаданных и повторный вывод рёбер остаются O(N + E); TUI достигает около
  500 MiB, обычная stat-сверка превышает секунду. Перед beta оптимизировать
  подтверждённые узкие места либо явно согласовать пересмотр бюджета.
  Reverse dependencies и новый сервис заранее не требуются.
- **suggestion: S-2.** Ранний бюджет startup <50 мс пока не подтверждён:
  готовый cached-каталог даёт первый полезный кадр с p50 около 75 мс.
  Не подменять этот бюджет другим названием или пятью CLI-замерами.
  Отдельная проверка бюджетов остаётся условием beta, первые измерения — v0.2.

## Questions

Не осталось вопросов, блокирующих границы v0.2. Приёмка версии владельцем
и согласование будущих бюджетов не заменяются этим ревью.

## Praise

Индекс можно потерять, не теряя recovery. Прежний cached-граф не смешивается
с новыми рёбрами после частичной записи. Уведомления файловой системы не
считаются доказательством полноты, а обновление каталога не требует демона.
Выбранные библиотеки используются реальными сценариями, без async-runtime,
нового workspace или абстракций для единственного исполнителя.
