# Проверка поиска, индекса и параллельной работы v0.2

Автор: Igor Kramar. 2026-10-30.

Область — [план v0.2](../../plans/2026-10-30-v0.2-search-index-concurrency.md)
поверх принятого и слитого v0.1. Реализованы SQLite/FTS5, общий resolver,
stat/full/cached, запросы CLI/JSON/JSONL и фоновые операции минимального TUI.
Полный ежедневный TUI, правила lint и перенос данных остаются следующим этапам.

## Проверенные сценарии

- Полный файловый каталог и инкрементальный индекс дают одинаковые диагностики
  и граф. Проверены rename/delete, title/alias, коллизии aliases, повторный ULID,
  invalid YAML/UTF-8, жизненный цикл вложения и реальное переключение git-веток.
  Full замечает изменения с прежними размером и mtime; cached сохраняет прежнее
  согласованное поколение, включая тело show и разрешённые рёбра.
- SQLite действительно содержит FTS5. Unicode-поиск, экранирование обычного
  запроса, явный FTS-синтаксис, literal/regex, fuzzy title/alias, пагинация,
  ошибки синтаксиса и отмена проверены отдельно. Поиск не меняет Markdown.
- Два CLI принимают stdin одновременно: каждый принятый текст сохранён один
  раз, ID различаются. Занятый writer-lock даёт явный отказ с повтором.
  Занятая SQLite ограничивает ожидание; rebuild не удаляет и не заменяет БД.
- Недоступный индекс после capture/link/edit/publish не отменяет сохранение:
  saved:true, ID/path и index_stale сохраняются, в том числе в составном new
  и частичной ошибке publish. Raw и файловое recovery доступны без SQLite.
- JSON/JSONL новых команд содержат фактическую freshness/generation, warnings,
  complete и truncated; JSONL завершает summary. Path выдаёт обычные абсолютные
  пути или точный NUL-поток. Невалидный UTF-8 корня отклоняется до создания vault.
- TUI: ввод, resize и навигация работают при фоне; старые IDs не заменяют
  preview/search/picker. Очереди ограничены; отмена чтения не отменяет принятую
  запись. Ошибка терминала завершает принятую запись один раз, форма остаётся
  при отказе. Fuzzy ввод кириллицы и быстро заменяемый поиск проверены через PTY.
- Watcher замечает CLI и внешнее редактирование/переименование. Потеря событий
  требует full; периодический full раз в минуту страхует отсутствие уведомления.
  На простое без изменения поколения терминал не получает новых кадров.
- Внешний редактор единолично получает stdin после восстановления терминала;
  конкурентный CLI работает. Выход, сигналы и ошибки возвращают termios,
  alternate screen, bracketed paste и cursor. Без TTY скрытой интерактивности нет.

## Проверки владельца ветки

На Linux x86_64 проходят **79 Rust-тестов** на Rust **1.89.0** и **1.99.1**,
all-targets clippy, fmt, YAML-стенд с 32 сценариями production parser,
самопроверка генератора, полный PTY и проверки внешних процессов.
MSRV проверен отдельным настоящим toolchain. CI повторяет набор на Linux
1.89/stable и macOS stable; статус конкретного head подтверждают checks PR.

```sh

cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings

python3 tools/corpus.py --self-check

python3 tools/test_tui.py
python3 tools/test_external.py
```

## Ревью

Десять локальных проверяющих охватили корректность, стандарты, тесты,
поддерживаемость, машинный доступ, прежние recovery-уроки, безопасность,
производительность, API-контракт и надёжность. Два замечания прошли отдельную
валидацию: `#1` — ошибка классификации отмены во время загрузки SQLite-каталога;
`#2` — недостающая прямая ссылка плана на ADR-0009. Первое закрыто общим
преобразованием отмены и регрессией уже начавшегося чтения, второе — ссылкой.
Архитектурные границы рассматриваются в
[отдельном ревью](2026-10-30-v0.2-architecture-review.md).

Независимый внешний проход запущен, но не дал пригодного результата из-за
ошибки обновления OAuth в его контексте выполнения. Независимое подтверждение
другой моделью не заявляется. Полный прогон делал владелец ветки,
проверяющие выполняли чтение и точечную валидацию.

Первый удалённый CI выявил две гонки. На macOS фоновая ошибка каталога
могла скрыть foreground-сообщение «Текст НЕ подтверждён» с открытой формой;
ошибка каталога теперь имеет отдельное состояние и видна одновременно
с результатом пользовательской операции. Детерминированный unit сначала
падал, затем проверил сохранность формы и сообщения после Catalog Err/Ok
с предупреждением; TestBackend подтверждает видимый текст.
Вторая гонка была в PTY: «Файлы сверены» ещё не означает готовность preview.
Стенд ждёт исчезновения существующих маркеров загрузки каталога/предпросмотра
и затем проверяет прежнее строгое отсутствие новых байтов. Keeper, EOF/EIO
и проверки termios/alternate/bracketed/cursor не ослаблены.

Следующий macOS-прогон выявил ещё один преждевременный PTY-барьер:
японский заголовок в общем списке считался готовым fuzzy-результатом
до обработки вставленного запроса. Теперь стенд проверяет заголовок с точным
запросом, завершение поиска и ID выбранного кандидата. Проверка четырёх
состояний экрана воспроизводит прежний ложный успех. Ранний Enter по-прежнему
не подтверждает устаревшую цель; после видимого отказа проверяется отсутствие
ссылки и выполняется явный Enter. Если актуальная выдача уже готова,
первый Enter законно может завершить выбор. Код приложения не менялся.

Ещё один MSRV-прогон обнаружил ожидание видимости файла вместо подтверждения
записи: CLI edit запускался, пока TUI link после atomic replace ещё завершал
recovery/fsync под vault-lock. Стенд ждёт ACK с ID/path, закрытого picker и
отсутствия «Сохранение…» в трёх связанных местах link/publish.
Подтверждён немедленный неблокирующий захват lock после ACK; отдельный сценарий
по-прежнему строго проверяет CLI capture при открытом редакторе. Повторы
edit/new и ослабление lock_busy-проверок не добавлены.

## Производительность

Linux 7.2.8 x86_64, Intel i9-10900K (10 ядер/20 потоков), около 31.2 GiB RAM,
Btrfs на локальном зашифрованном SSD, Rust 1.99.1 release. Прогрет файловый
кэш ОС; первый rebuild начинает с нового SQLite. Это синтетический корпус,
а не оценка качества поиска на реальной базе. Корпус generator_version=2:
медиана тела 4218.5/4219 байт, 3–10 исходящих связей кроме root,
32 497/324 997 разрешённых рёбер; последние три тела 50k около 256 KiB.
Функциональные малые корпуса генератор не меняет.

Все исходные числа, SHA-256 бинарников/манифестов и серии сохранены в
[JSON измерений](2026-10-30-v0.2-performance.json). CLI и оптимизированный startup
сняты с бинарника bf7cb489; steady TUI — с 81d08327 до оптимизации startup.
Вторая сборка добавляет cached-первый кадр с последующей stat-сверкой;
результат steady не выдаётся за повторное измерение нового бинарника.
Оба замера предшествуют финальному исправлению классификации отмены SQLite
и отображения фоновых ошибок TUI. Они не выдаются за повторный benchmark
последней сборки; обычный алгоритм поиска без отмены не менялся.

Первый полезный кадр с готовым индексом на 5k: десять запусков,
p50 **74.7 мс**, наблюдаемый p95 **106.3 мс**. PTY-reader ждёт первых байтов
через select и читает без искусственного интервала тишины; время включает
Python keeper и разбор видимых ячеек. Навигация: 30 пар refresh + j/k.
66 секунд простоя включают периодическую сверку; пустой терминальный цикл
на 11-секундном окне дал 0% в разрешении счётчика CPU. Это локальные наблюдения,
не статистическая гарантия и не измерение холодного диска.

для обхода этих ограничений не вводились.

## Ограничения и приёмка

Результаты локальны для указанной среды. Физический power-cut, полный fuzzing,
искусственная panic через PTY, suspend/resume и полная терминальная/платформенная
матрица остаются beta. Недель ежедневной эксплуатации этот прогон не заменяет.
Остаются непокрытыми детерминированная гонка generation/revision между подготовкой
и commit, отмена внутри write transaction с проверкой отката всех таблиц,
отказ уже зарегистрированного watcher и исчерпание reconcile-retries.
Fuzzy после каждого ввода и graph/links требуют отдельных измерений на 5k/50k;
нынешние CLI-серии их не измеряют. Эти пробелы тестов сохранены из ревью,
а не объявлены прошедшими сценариями.
Приёмка версии, слияние нового PR и публикация релиза — отдельные действия.
