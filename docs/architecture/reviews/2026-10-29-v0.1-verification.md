# Проверка минимального цикла v0.1

Автор: Igor Kramar. 2026-10-29.

Область — [план v0.1](../../plans/2026-10-29-v0.1-minimal-note-cycle.md)
после принятого этапа 0. Реализованы CLI/JSON/JSONL, минимальный TUI,
общее ядро, формат, файловая запись и восстановление. Поиск и SQLite
относятся к v0.2; готовность всего состава 1.0 не заявляется.

## Проверенные сценарии

- CLI: init → new с отказом публикации и сохранённым draft → read-only show
  → link → publish. ID сохраняется, опубликованный файл читается как Markdown.
- TUI на том же формате vault: capture → внешний редактор → выбор связи
  → publish; new с отказом публикации показывает rule IDs и оставляет Inbox.
- Unicode, многострочная вставка, grapheme Backspace, resize и сохранение
  выбора/ввода; Esc с продолжением или явным discard; отсутствие перерисовки
  на простое.
- CLI при открытом TUI и явная сверка; два CLI при занятом writer-lock
  отказывают без перезаписи. Редактор не удерживает блокировку.
- Ошибка редактора и конфликт с внешней версией сохраняют рабочую копию.
  q, Ctrl-C, SIGINT и ошибка редактора восстанавливают termios,
  alternate screen, bracketed paste и cursor.
- При недоступной записи TUI сохраняет форму и допускает повтор после
  устранения причины. Без TTY нет raw mode, редактора или скрытых вопросов.
- JSON/JSONL edit с печатающим редактором: stdout содержит только машинный
  ответ, вывод редактора идёт в stderr. JSONL завершается summary.
- Безопасные пути, symlinks, special files, существующая цель, повторный ULID,
  права записи и недоверенный recovery-план дают явный отказ.
- Прерывание подготовки, записи, переноса и отката; повтор resume/restore
  идемпотентен. Path-specific отказ fsync после rename/unlink не позволяет
  завершить план до повторного подтверждения каталога. Init также подтверждает
  ancestors нового vault.

## Ревью и исправления

Проверка упрощений убрала повторный parse заметки, повторные вычисления хеша,
лишнюю запись уже сохранённого плана и отрисовку полностью закрытого preview.
Экранирование терминальных control-символов общее для CLI/TUI.

Ревью охватило корректность, стандарты, тесты, поддержку, машинный доступ,
безопасность, производительность, API-контракт, надёжность и adversarial-сценарии.
Четыре замечания независимо подтверждены по коду и контрактам, затем исправлены:

| Замечание | Исправление и регрессия |
|---|---|
| `#1`, P1: I/O после сохранения связи теряет saved/ID/path | Общий контекст ошибки publish; CLI-тест с недоступным корнем и доступным inbox проверяет сохранённую связь, saved, ID/path и recovery. |
| `#2`, P2: complete зависит от валидности заметки | Полнота отделена от диагностики структуры; полностью прочитанный invalid YAML даёт complete=true, ошибка чтения — false. |
| `#3`, P2: редактор загрязняет JSON stdout | Stdout редактора направлен в дубликат stderr; PTY проверяет JSON и JSONL с маркером и ANSI. |
| `#4`, P2: resume пропускает fsync существующей цели | Повторное подтверждение каталогов в resume/restore; имитация отказа после фактического изменения проверяет повторный отказ и последующий успешный retry. |

Дополнительно исправлены подготовка до появления work, прерванный restore,
повторный init/doctor с несовместимым форматом, обход duplicate ID через recovery,
ссылка внутри незакрытого literal-блока и распознавание aliases с двоеточием.
Каждый существенный дефект сопровождался воспроизводящей проверкой.

[Архитектурное ревью](2026-10-29-v0.1-architecture-review.md) подтверждает
границы ADR-0005–0008. Независимая проверка через другую модель не заявляется:
ранее наблюдалась ошибка OAuth в её контексте выполнения, использована локальная
adversarial-проверка. Полный прогон выполнял владелец ветки, ревьюеры — точечные.

## Выполненные проверки

На Linux x86_64 полный набор **53 Rust-теста** проходит на Rust **1.89.0**
и **1.99.1**. MSRV проверен настоящим отдельным toolchain, а не только
полем rust-version в манифесте. YAML-стенд дополнительно проходит 32 сценария
через production parser. Форматирование, clippy, самопроверка корпусов и PTY
проходят.

```sh
cargo test --locked
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --manifest-path tools/format-probe/Cargo.toml
python3 tools/corpus.py --self-check
cargo build --locked
python3 tools/test_tui.py
```

[CI](../../../.github/workflows/ci.yml) запускает эти проверки на Linux
с Rust 1.89/stable и на macOS со stable. Фактический статус удалённого прогона
виден в checks соответствующего PR; этот отчёт фиксирует локальные результаты.

## Ограничения и приёмка

Физический power-cut не моделировался; fault injection проверяет протокол
и поведение при отказах системных операций. Panic cleanup реализован hook/Drop,
но искусственная panic через PTY ещё не проверена. Suspend/resume, полная
платформенная и терминальная матрица относятся к beta.

Каталог и resolver v0.1 выполняют полный обход, TUI работает синхронно.
Измерения поиска/индекса на 5k/50k относятся к v0.2. Недели ежедневной
эксплуатации beta/1.0 этой проверкой не заменяются.

Приёмка версии владельцем и публикация релиза — отдельные действия.
Практический урок по recovery сохранён
[отдельно](../../solutions/logic-errors/recovery-intent-before-payload.md).
