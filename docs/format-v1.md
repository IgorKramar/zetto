Примеры и ожидаемые исходы — в [корпусе](../tests/corpus/README.md).

## Размещение и версии

Корень: `.zettorc` (TOML), опубликованные `*.md`, `inbox/*.md`, `assets/`,
`.zetto/recovery/`, `.zetto/locks/`. Обход заметок только на одном уровне
корня и inbox, регистр расширения — `.md`. Иные файлы не удаляются.
Вложенные Markdown в assets не становятся заметками. Управляемые пути
не содержат `..`, абсолютных путей и symlink-компонентов. ID нельзя
использовать как произвольный путь. Хранилища на сетевых ФС вне гарантий 1.0.

```toml
config_version = 1
format_version = 1
root_id = "01ARZ3NDEKTSV4RRFFQ69G5FAV"

[lint]
preset = "recommended-luhmann"
```

Версия заметки не дублируется в каждом файле; отдельный файл без версии
трактуется как v1. Неизвестный major формата/конфигурации запрещает все
управляемые изменения, включая автоматические исправления; raw-чтение
доступно. Переезд vault создаёт новый локальный индекс и UI-state,
пользовательские файлы не мигрируются автоматически.

## Байты и frontmatter

Файл — UTF-8 без BOM. LF и CRLF читаются; новый файл использует LF.
Frontmatter начинается первой строкой `---`, заканчивается следующей
отдельной строкой `---` или `...`. Разделители без пробелов. YAML между
ними — ровно один mapping. Остальные байты — body, включая ведущие пустые
строки. Разделители в теле/коде не открывают второй frontmatter.
Нет начала/конца, не-UTF-8 или неоднозначный YAML → диагностика файла,
запрет управляемой записи, raw-чтение и recovery остаются доступны.

| Поле | Тип и поведение |
|---|---|
| `id` | Обязательная строка: 26 ASCII символов `0123456789ABCDEFGHJKMNPQRSTVWXYZ`, первый `0…7`; декодируемый 128-битный ULID. Нижний регистр не нормализуется. Не меняется при retitle. |
| `title` | Обязательная UTF-8 строка. Пустая/пробельная допустима для inbox, запрещает publish; не выводится автоматически из H1. |
| `tags` | Необязательный список строк. Одиночная строка читается как один тег с `zetto/non-canonical-tag-format`; сохраняется без скрытого исправления. |
| `aliases` | Необязательный список строк. Пустые элементы дают предупреждение и не участвуют в resolver. |
| `created`, `updated` | Необязательные строки RFC 3339. Новая заметка получает UTC `created`; имеющийся сохраняется. Неверное значение даёт предупреждение и сохраняется. `updated` меняется только управляемым сохранением изменённого тела; внешнее изменение и чтение его не обновляют. `x-skip-updated: true` отключает обновление. |
| Остальные | Сохраняются как значения; `x-*` без предупреждения, остальные дают `zetto/unknown-frontmatter-field`. |

Неверный тип/отсутствие обязательного поля блокирует управляемую запись.
Ошибки tags/aliases/timestamps не делают валидные id/title невидимыми:
неверное optional-поле сохраняется в дереве, исключается из производных
тегов/aliases и даёт warning. Это уточняет прежний error для invalid-tags.
Одинаковый ключ YAML на любом уровне — ошибка разбора, без last-wins.

Поддерживаемый YAML-профиль: строки (включая многострочные `|`/`>`), null,
bool `true`/`false`, конечные числа в диапазоне `serde_json::Number`, списки,
вложенные mappings со строковыми скалярными ключами, anchors/aliases и merge
keys с сохранением **результирующих значений**. Ключи десериализуются как
строки; числовые/boolean/null ключи запрещены, числовое написание требует
кавычек (`"1"`, `"0xB"`). Запрещено молча сводить разные YAML-ключи к одной
строке: это теряет неизвестное значение ещё до проверки writer.
`no`, `yes`, `on`, `off` — строки (YAML 1.2). Пользовательские tags, `!include`,
нечисловые float (`.nan`, `.inf`), сложные ключи и циклические aliases
не поддерживаются: ошибка, без исполнения или потери неизвестного значения.
Нельзя применять writer к файлу, который не помещается в этот профиль.

Writer сериализует полное дерево, заменяя только явно изменённые поля.
Не обещает исходный порядок ключей, кавычки, комментарии, anchors и стиль
многострочных значений. Каноническая повторная запись идемпотентна;
произвольный read→write не является побайтно тождественным. Тело при
операции над метаданными сохраняется побайтно. Резервная версия обязательна.
При чтении даже canonical writer не вызывается.

Стенд проверяет семантическую сохранность выбранного корпуса, а не любую
возможную YAML-конструкцию и не весь будущий parser frontmatter/Markdown.
Лимиты входа/глубины должны возвращать `zetto/resource-limit`, не пропускать
файл молча; конкретные бюджеты приложения фиксируются с parser в v0.1.

## Производные теги (v0.2)

Каталог объединяет YAML tags и inline `#тег`: после начала тела или пробельного
символа, далее один или больше Unicode letters/digits, `_` или `-`.
Код, HTML, destinations ссылок и экранированный `\#` не образуют inline tag.
Граница проверяется в исходном тексте, а не в отдельном Markdown-событии.
Теги уникальны на файл; `tags` считает число файлов. Это производное
представление, чтение не переносит inline tags во frontmatter.

## Имена

`<ULID>-<slug>.md`, при пустом slug — `<ULID>.md`. Slug — результат
`slug::slugify(title)`, ASCII lowercase, цифры и `-`, до 60 символов;
обрезание по границе слова, а если слово длиннее 60 — обрезание самого слова.
Пустой результат → имя без slug. Максимум 90 ASCII байтов: 26+1+60+3.
`id` во frontmatter должен совпадать с префиксом имени. Один ID в нескольких
файлах — `zetto/duplicate-id`; ни один автоматически не становится целью.
Несовпадение имени/ID — `zetto/id-filename-mismatch`, запись блокируется.
Устаревший slug — `zetto/slug-mismatch` (warning), исправление только явное.
`slug_locked: true` сохраняется как историческое расширение и отключает
согласование slug при retitle/resync; предупреждение unknown-field для него
не выдаётся. Смена title не меняет ID или входящие канонические связи.

## Markdown и координаты

CommonMark + tables, strikethrough, task lists и wikilinks. Footnotes, math,
heading attributes и embeds не включаются как специальные расширения 1.0.
HTML и ANSI/OSC из файла не исполняются. Inline/fenced/indented code
не содержит рёбер графа. Markdown link/reference link и `[[target|display]]`
разбираются парсером, без regex-замен по всему тексту.

Диапазон ссылки/диагностики: нулевые UTF-8 byte offsets `[start,end)`
от начала полного файла; line/column для человека — с 1, column в Unicode
скалярах. Для YAML-ошибок без точного диапазона `span: null`.
Wikilink делится по первому `|`, остальные `|` — display. Пустой display
использует title цели. Неразрешённое отображается буквально. Display не
меняет идентичность ссылки. `![[...]]`, `#heading` и `#^block` сохраняются
буквально и диагностируются, не становятся fallback-ссылкой на целую заметку.

## Resolver (общий для всех потребителей)

Сканер хранит каждую запись файла отдельно, включая ошибочную и дубликаты.
На ID могут указывать только структурно валидные файлы с совпадающим именем.
Видимость дубликата/ошибки не зависит от включённого пресета.

Wikilink:

1. Пустая цель → broken; URL → `zetto/external-url-as-wikilink`;
   embeds/anchors/block refs → unsupported, без дальнейшего fallback.
2. Цель длиной 26 символов без `/`, `\\` и расширения считается кандидатом
   ULID. Невалидный алфавит/регистр/overflow → invalid, без alias fallback.
   Валидная → lookup frontmatter ID во всём корне+inbox: 0 broken,
   1 resolved, более одного ambiguous (даже если один файл повреждён).
3. Остальные цели: точное совпадение управляемого относительного filename
   (с `.md` либо без расширения), затем alias (trim + Unicode lowercase),
   затем точное legacy basename без расширения по корню и inbox.
   На каждом шаге 0 → следующий, 1 → resolved, >1 → ambiguous и остановка.
   Произвольный title не участвует; title нужен для UI-поиска.

Обычная Markdown-ссылка:

1. `https`, `http`, `ftp`, `sftp`, `ssh`, `mailto` → external,
   не ребро. `file`, `javascript`, `data` и неизвестные схемы → unsafe,
   никогда не открываются автоматически.
2. Fragment → unsupported. Относительный путь декодируется ровно один раз
   как URL path, нормализуется относительно **исходного** файла и проверяется
   внутри vault; `..` и symlink-компоненты запрещены. Поэтому из inbox
   создаваемые связи используют wikilink, а не `../...`.
3. Существующий управляемый файл → resolved при валидной уникальной
   идентичности; asset → attachment. Несуществующий basename с полным
   ULID-префиксом → lookup ID (совместимость retitle); иначе legacy basename.
   Alias fallback для Markdown path не используется. Stale filename
   после ID-fallback даёт `zetto/stale-link-path`.

Ссылки на себя и черновик можно показать, но они не выполняют условие
публикации. Все новые внутренние связи writer создаёт `[[ULID]]` или
`[[ULID|display]]`. Отсутствующая цель — `zetto/no-broken-link`, несколько
целей — `zetto/ambiguous-link`. Проверка publish перечитывает цели.

## Сохранность и совместимость

Протокол записи/восстановления — [ADR-0006](architecture/decisions/0006-safe-writes-and-recovery.md).
Inbox и recovery — первичные данные; индекс можно удалить и пересобрать.
Нет общей атомарности нескольких файлов и SQLite.
Уточнение спецификации не меняет значение существующих ссылок молча:
такое изменение требует ADR, новой версии и явной миграции.
