# v0.1: полный минимальный цикл заметки

Автор: Igor Kramar. Основание: принятый [этап 0](../contracts/stage-0.md),
ADR-0005–0008 и план владельца от 2026-10-29.

## Результат

Один Cargo package с библиотекой и бинарником. Пользователь создаёт vault,
сохраняет мысль в inbox, редактирует, связывает и публикует через CLI и
минимальный TUI на одном хранилище. CLI/JSON и TUI вызывают общие операции.
Markdown остаётся источником истины; индекс v0.1 — обход в памяти.

## Порядок реализации

1. Модель/формат: ULID, slug, frontmatter, независимые диагностики,
   сохранение неизвестных значений и тела, Markdown-ссылки с byte ranges.
2. Файлы/восстановление: безопасные пути, OS-lock, атомарная запись,
   no-clobber, hash/backup, план публикации с resume/restore.
3. Операции: init/capture/show/list/edit/link/publish/new, каталог в памяти
   и resolver по format-v1; рабочая копия редактора без shell и hash conflict.
4. CLI/JSON: команды v0.1 по принятому контракту, stdin/TTY, discovery vault,
   полные структурированные ответы при успехе и ошибке.
5. TUI: список/предпросмотр, ввод, редактор, выбор связи, публикация,
   Gruvbox и восстановление терминала. Палитра/полный Focus относятся к v0.3.
6. Проверки/поставка: сборка, fmt, clippy, CI, сквозной CLI и PTY-сценарий,
   документация первого запуска и восстановления, ревью результата.

## Принятые границы

- [ADR-0005](../architecture/decisions/0005-format-layout-and-resolution.md):
  чтение не меняет заметки, дубликат ID/alias неоднозначен, YAML сохраняет значения.
- [ADR-0006](../architecture/decisions/0006-safe-writes-and-recovery.md):
  текст/backup/план восстановления не зависят от SQLite.
- [ADR-0007](../architecture/decisions/0007-shared-cli-tui-core.md):
  общее ядро, конкретные типы, зависимости вводятся с потребляющим кодом.
- [ADR-0008](../architecture/decisions/0008-capture-publish-and-root.md):
  capture без связи; publish с title и связью на другую опубликованную;
  одно root-исключение; неудача new оставляет draft и ID/путь.

Нет SQLite/FTS/watcher, дополнительных тем, импорта и полнотекстового поиска.
Минимальное recovery доступно уже сейчас, завершённый doctor — v0.5.
Библиотеки формата из этапа 0 переиспользуются с теми же ограничениями.
Файловая блокировка — std File::try_lock; создание/замена — tempfile на
том же томе; UI — ratatui/crossterm; CLI — clap. Версии фиксируются lockfile,
MSRV сверяется с реальным графом зависимостей.

## Проверки и критерии завершения

- YAML-корпус этапа 0 проходит против production parser. Ожидаемые
  Markdown-диапазоны LF/CRLF и resolver-примеры становятся тестами.
- Реальные временные vault: полный init → capture → edit → link → publish;
  cat читает созданную заметку. Неудачный new/publish сохраняет тело.
- Неверный YAML/ID, filename mismatch, повторный ULID, опасный путь,
  существующая цель, отсутствие прав, занятая блокировка дают явный отказ.
- Ошибка редактора и внешний конфликт сохраняют исходник/копию.
  Lock не удерживается во время редактора; два процесса не затирают друг друга.
- Прерывание между шагами publish возобновляется/откатывается по файловому
  плану без SQLite; recovery-пути не могут выйти из vault.
- Без TTY нет скрытых вопросов/raw mode; JSON-ошибки имеют стабильные коды.
- PTY: основные действия TUI, вставка/resize, выход и ошибка восстанавливают
  терминал; редактирование использует то же ядро.
- cargo test, fmt, clippy проходят; CI запускает эти же проверки.

Прогресс фиксируется коммитами и результатами проверок отдельно от тела плана.
Публикация релиза требует отдельного действия владельца.
