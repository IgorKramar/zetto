# Этап 0: принятые контракты

Автор: Igor Kramar. 2026-10-29.

**Состояние:** контракты и макеты приняты Igor Kramar 2026-10-29,
проверочный стенд проходит проверки. Этап 0 завершён; реализация v0.1
следует после интеграции этого пакета в main. Готовность 1.0 не заявляется.
Источник намерения — план «от проектирования до 1.0» владельца от 2026-10-29
и [архитектурное предложение](../architecture/research/2026-10-29-zetto-1.0-design.md).

## Принятые решения

| Решение | Артефакт | Изменение действующего контракта |
|---|---|---|
| Формат/размещение/resolver | [ADR-0005](../architecture/decisions/0005-format-layout-and-resolution.md), [format-v1](../format-v1.md) | Нет записи при чтении, нет alias-tiebreak, frontmatter ID — истина, YAML сохраняет значения, не оформление |
| Сохранность/конкуренция | [ADR-0006](../architecture/decisions/0006-safe-writes-and-recovery.md) | OS-lock + хеш + backup/recovery вместо single-writer/mtime |
| Ядро/адаптеры | [ADR-0007](../architecture/decisions/0007-shared-cli-tui-core.md), [CLI](cli-v1.md) | CLI и TUI вызывают одинаковые операции и получают общие диагностики |
| Capture/publish/root | [ADR-0008](../architecture/decisions/0008-capture-publish-and-root.md) | Сохранение без связи в inbox, строгая публикация, одно явное root-исключение; меняется смысл link-before-save |
| Пользовательский интерфейс | [Три макета, клавиши и палитра](tui-v1.md) | Library/Focus/Inbox, Gruvbox и поведение ошибок/ввода |

ADR-0005–0008 имеют статус Accepted. В прежних ADR указаны заменённые
разделы и нормативные уточнения; исторический текст сохранён.
STRATEGY, ARCHITECTURE и decision-map согласованы с принятым контрактом.
Приёмка контрактов разрешает реализацию v0.1; она не заменяет приёмку
работающего приложения по сценариям следующих версий.

## Сценарии до реализации

| Сценарий | Ожидаемый результат |
|---|---|
| Первый запуск | Без vault — понятная ошибка и `init`; init без вопросов создаёт config/root. Root — обычный `.md`, исключение видно. Без TTY raw mode не включается. |
| Неудачный new/publish | Сначала сохранён inbox, затем exit 1 / draft_saved с тем же ID/путём и причинами. Publish существующего draft не создаёт ещё один draft. |
| Ошибка редактора | Оригинал и устойчивая рабочая копия сохраняются, exit 4, путь recovery; для new также путь draft. |
| Оригинал изменился во время редактора | Exit 3/conflict, обе версии остаются, никакого автоматического слияния или записи поверх изменённого оригинала. |
| Сбой между созданием published и удалением inbox | План позволяет определить шаг по хешам; чтение показывает дубликат и незавершённую операцию; resume/restore без SQLite. |
| Ошибка индекса после подтверждённой записи | Exit 0, saved true, index_stale; текст виден через cat; повторять создание не нужно. |
| Неоднозначный alias/ID | Кандидаты и ambiguous, автоматического первого нет; publish отвергается. |
| Чтение старого slug или external update | Диагностика без переименования и без записи updated; исправление только явное. |

## Данные и кэш

| Состав | Где | Жизненный цикл |
|---|---|---|
| Опубликованные, inbox, assets, .zettorc | Vault | Пользовательские данные, git/backup по выбору владельца |
| Планы, backups, editor work | `.zetto/recovery/` | Пользовательские данные восстановления; backup, без автоматической очистки |
| OS-lock handles | `.zetto/locks/` | Локальная координация; не удалять для обхода живого lock |
| SQLite/FTS, UI-state, logs | XDG cache/state, ключ канонического пути | Производный индекс пересоздаётся; UI-state теряется при очистке; логи не содержат тела по умолчанию |

## Состав и совместимость 1.0

| Версия | Обязательный пользовательский результат |
|---|---|
| 0.1 | CLI+минимальный TUI: init/capture/edit/link/publish/new; безопасная запись, recovery, JSON и CI; полный обход в памяти |
| 0.2 | Производный SQLite/FTS5, единый resolver, incremental/full parity, fresh/cached, поиск/links/graph/tags/path, watcher и параллельные процессы |
| 0.3 | Ежедневные Library/Focus/Inbox, палитра всех Action, локальный граф, resize и история; неделя использования |
| 0.4 | Общий lint и диагностики, пресеты, объяснения и только однозначные исправления |
| 0.5 | Двухпроходный Markdown/UUID import с resume, export/assets, doctor/resync, завершённые JSONL/NUL/completion/man и backup guide |
| beta | Заморозка функций, темы/клавиши, Unicode/PTY, Linux+macOS матрица, fuzzing, метрики и минимум две недели ежедневного использования |
| rc | Конкретные пакеты: upgrade/downgrade, crash/permissions/space/recovery, license/advisories, SQLite/FTS5, checksums/provenance |
| 1.0 | Документация, smoke установленных пакетов, демонстрация; публикация отдельным действием владельца |

Переход между версиями — после проверок предыдущей, а не по сроку.
Patch исправляет дефекты без изменения стабильных контрактов. Версии
бинарника, note format, vault config, JSON schema и индекса независимы.
После 1.0: несовместимый CLI/JSON/config/format требует major и политики
миграции; additive необязательные поля допустимы без переписывания заметок.
Индекс всегда пересоздаваем, его schema не мигрирует пользовательский Markdown.
До beta возможны только явно документированные изменения контрактов с ADR.

Поддерживаемая область 1.0: один автор, несколько локальных процессов,
один vault на запуск, локальная ФС, Linux x86_64/aarch64 и macOS Intel/ARM
после фактической проверки. Без обязательных rg/fzf/Nerd Font.
Вне 1.0: демон, LSP, cloud-sync, совместное редактирование, динамические
плагины, собственный полнотекстовый редактор, глобальная физическая симуляция
графа и обещание двустороннего произвольного Obsidian vault.

Приёмка макетов/ADR выполнена владельцем отдельно от стенда.
Неделя ежедневного TUI и две недели beta остаются критериями будущих версий.
Разрешена интеграция пакета в main; публикация релиза остаётся отдельным
явным действием владельца.
