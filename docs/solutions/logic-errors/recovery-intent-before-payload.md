# Сохранять намерение до подготовки файлов восстановления

Автор: Igor Kramar. Исправление принято с v0.1 в PR #2.

## Проблема

Backup и рабочая копия сами по себе не описывают, какую операцию нужно
закончить после сбоя. Если план создаётся после них, прерывание подготовки
попадает вне протокола восстановления. Особенно заметно это для `init`:
пользовательского исходника, из которого можно восстановить work, ещё нет.

## Причина

Подготовка файлов рассматривалась как действие до транзакционного протокола.
Но она тоже состоит из отдельных записей и может прерваться после любой.
Атомарная замена одного файла не делает всю подготовку атомарной.

## Решение

В [vault.rs](../../../src/vault.rs) `make_plan` сначала подтверждает
`plan.json` в состоянии `Preparing`, затем вызывает `prepare_files`:

```rust
self.save_plan(&plan)?;
checkpoint("intent_saved")?;
self.prepare_files(plan, base, work)
```

План содержит ожидаемые хеши и относительные пути. Для `init` он дополнительно
содержит конфигурацию и исходный текст root. После подтверждения backup/work
состояние меняется на `Prepared` или `Editing`. Resume проверяет существующие
копии по хешам и достраивает отсутствующие; если новая версия не успела
сохраниться и её нельзя восстановить из исходника, требуется явный restore.

Состояние `Restoring` аналогично сохраняется до первого изменения отката:
повторный resume заканчивает начатую отмену, а не возвращается к публикации.

## Почему работает

После первой подтверждённой записи есть намерение, позволяющее отличить
незавершённую подготовку от законченной операции. Протокол не угадывает
назначение файлов по именам и не зависит от будущего SQLite-индекса.
Каталог без плана не даёт права менять заметки.

## Проверка и предотвращение

`vault::tests::init_resumes_before_payload_preparation_finishes` и
`vault::tests::interrupted_writes_resume_from_actual_files` в
[vault/tests.rs](../../../src/vault/tests.rs) прерывают протокол на контрольных точках.
Перед добавлением шага переноса или отката добавляйте точку прерывания и
проверяйте возобновление по файлам, а не только записанному state.

```sh
cargo test --locked --lib vault::tests
```

Основание: [ADR-0006](../../architecture/decisions/0006-safe-writes-and-recovery.md).
План не заменяет независимый backup и не даёт транзакции с произвольным
внешним редактором или git.
